# Contributing

Thanks for your interest in contributing to this project. The Warriors Recomp and Freedom Fighters Recomp repositories contain project code and documentation only; they must never contain game files.

## Before you start

- Read the project README and any relevant documentation before proposing a change.
- For substantial changes, open an issue first to discuss the approach and avoid duplicated effort.
- Keep contributions focused and make one logical change per pull request.
- Do not include game data or material extracted from a game disc.

## Branches and pull requests

- Create a topic branch from the repository's current default branch. Do not work directly on `main`.
- Use a short, descriptive branch name, such as `docs/update-setup-guide` or `fix/controller-mapping`.
- Open a pull request targeting the repository's current default branch.
- Explain the problem and the proposed change, link any related issue, and list the checks you ran.
- Keep the pull request limited to the intended change. Update it in response to review and resolve discussion before requesting another review.

## Code and formatting

- Follow the conventions already used in the files you are changing.
- Check for repository-specific formatting or build instructions before editing; do not introduce a new style or tool without discussing it.
- Prefer small, readable changes. Add or update tests when the project has relevant tests.
- Do not claim a build, test, or manual check passed unless you ran it and can report the result.

## Game files and legal copies

- Never commit, upload, or distribute game files, disc images, executables, dumps, extracted code, or original game assets. This includes ISOs, XBEs, and other title-specific files.
- Do not attach game files to issues or pull requests. Do not provide download links to them.
- Testing must use a copy that the tester is legally entitled to use, obtained independently. The project does not provide or host game copies.
- Contributions must be original work that you have the right to submit. Do not submit material copied from game files or other sources unless its license clearly permits the use and the project maintainer has approved the proposed inclusion.
- If you are unsure whether a file or change is appropriate, ask in an issue before submitting it.

## Reporting bugs

Open an issue in the relevant repository and include:

- A clear, concise description of the problem and what you expected to happen.
- Steps to reproduce the issue, including relevant settings and the affected project version or commit.
- Your operating system and relevant hardware/software details.
- The exact error text or a log excerpt, with personal information and local file paths removed.
- Whether the issue is reproducible and any troubleshooting already attempted.

Do not attach or paste game data, copyrighted assets, credentials, or other sensitive material.
